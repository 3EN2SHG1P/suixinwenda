# 发布流程（维护者）

> 文档索引：[docs/README.md](../README.md) ｜ 门禁与打包：[docs/打包与发布.md](../打包与发布.md)

本文件只服务仓库维护者：把版本推到 GitHub Releases。自己出安装包不需要走这里，
按 [打包与发布 第 2 节](../打包与发布.md) 即可。

---

## 1. 一条路径：tag 触发

发布只有这一条路径：**打 tag → 推 tag → 工作流自动出包并挂到 Release**。
手工上传安装包会让「Release 里的文件」与「某个 commit」失去对应关系，出问题无法复现。

1. 改版本号（只改 `desktop/package.json`）→ `npm run version:sync` →（在 `backend/` 下）`uv lock`
2. 把本次变化写进 `CHANGELOG.md` 的 `[Unreleased]`；发版时改名为 `## [x.y.z] - YYYY-MM-DD`
3. 提交并推送 `main`，等 CI 全绿
4. 打 tag 并推送：

   ```powershell
   git tag -a v0.1.0 -m "随心问答 0.1.0"
   git push origin v0.1.0
   ```

`.github/workflows/release.yml` 随后在 `windows-latest` 上：

- 校验 tag 与 `desktop/package.json` 的版本一致（`v0.2.0` 配 `0.1.0` 会直接失败，避免产物名与 Release 名互相矛盾）
- `uv sync --frozen` + `npm ci` → `npm run dist`（后端 PyInstaller + NSIS + portable）
- 确认两个 exe 与 `dist/SHA256SUMS.txt` 都在，缺一个就失败（不静默发出半个 Release）
- 用 `gh release create` 建 Release（`--generate-notes`），上传 Setup / Portable / `SHA256SUMS.txt`

---

## 2. 要点

- Release 里**不带** `安装说明.txt`：中文文件名在 Windows runner 上传时容易出编码问题，
  内容已写进 README 与 [打包与发布](../打包与发布.md)
- 产物没有代码签名：首次运行会提示「未知发布者」，`SHA256SUMS.txt` 是用户唯一能核对完整性的凭据，必须上传
- 同名 Release 已存在时工作流会先删再建，重打同一个 tag 是安全的（会覆盖）
- 失败重试直接在 Actions 页面 Re-run；不要手工往 Release 里补文件，否则下次自动发版会与手工文件混在一起
- 明确不做：代码签名（无证书）、自动更新（本项目无更新服务）、macOS/Linux 产物（未适配）
