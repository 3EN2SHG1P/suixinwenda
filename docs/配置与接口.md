## 1. 环境变量

全部在 `backend/.env`（由 `.env.example` 复制，已被 `.gitignore` 忽略）。安装版的等价文件是
`%APPDATA%\suixinwenda-desktop\config.env`，由桌面端首次启动时从模板生成。

另有一组 `SUIXINWENDA_*` **运行期**变量不由 `.env` 提供（写进 `.env` 也不生效），全部由桌面端注入：

| 变量 | 谁设置 | 作用 |
|---|---|---|
| `SUIXINWENDA_ENV_FILE` | 桌面端托管启动时 | 指定后端读取哪个配置文件（安装版指向 `userData/config.env`），决定 `.env` 与打包态配置谁是唯一来源 |
| `SUIXINWENDA_MANAGED` | 桌面端托管启动时 | 置 `1` 表示后端由桌面端管理：健康检查回 `data.managed=true`、只允许绑回环地址、生命周期跟随父进程 |
| `SUIXINWENDA_PARENT_PID` | 桌面端托管启动时 | 父进程 pid（仅 Windows 生效）：父进程消失后后端自行退出，避免留下独占 8010 的孤儿进程；另有 stdin EOF 哨兵兜住 `uv` 中间层持有管道的情况 |
| `SUIXINWENDA_MODELS_FILE` | 桌面端启动模型时 | 运行期模型配置文件（含明文 Key，落在 `userData/runtime/`，进程退出即删）；不设则回落到 `.env` 的两模型逻辑 |
| `SUIXINWENDA_PROBE_HOST/PORT/USER/PASSWORD/NAME/SSL_CA/SSL_NO_VERIFY_IDENTITY` | 桌面端「测试连接」子进程 | 七个参数全部走环境变量：命令行参数在进程列表里明文可见，等于把口令写进系统日志 |
| `SUIXINWENDA_USER_DATA` | 自检 / 多开验证时手动设 | 覆盖 userData 目录，让 `npm run verify:packaged` 之类的自检不碰真实配置与备份 |

以下由 `backend/.env` 提供（安装版是 `config.env`，键名相同）：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `BACKEND_HOST` / `BACKEND_PORT` | `127.0.0.1` / `8010` | 后端监听地址与端口（`run.py` 读取，留空按 `127.0.0.1`）；**桌面端托管时强制 `127.0.0.1`**，写成 `0.0.0.0` 会被拒绝启动。要对外提供服务请手动跑 uvicorn，并先读 [PRIVACY.md](../PRIVACY.md) |
| `DB_BACKEND` | `sqlite` | `sqlite` / `mysql`；**留空**则看 `DB_HOST`：有值就是 mysql，没有就是 sqlite（老配置自动继续用 MySQL） |
| `DATA_DIR` | 空（= `backend/data`） | 数据目录：SQLite 文件与附件都在这里 |
| `DB_HOST` / `DB_PORT` | `127.0.0.1` / `3306` | 仅 MySQL 方案需要 |
| `DB_USER` / `DB_PASSWORD` | `root` / `123456` | 仅 MySQL 方案需要，默认与 `docker-compose.yml` 一致；**桌面端写入时密码存为 `DB_PASSWORD_ENC`（系统加密，Windows 走 DPAPI），文件里没有明文** |
| `DB_PASSWORD_ENC` | 空 | **不是手工填的项**（`.env.example` 里没有这一行，手写也不会被读）：桌面端写入存储配置时用它替代明文 `DB_PASSWORD`；后端无法解密，只会给出「用桌面端启动」的中文提示 |
| `DB_NAME` | `suixinwenda` | 仅 MySQL 方案需要，首次启动自动建表 |
| `DB_ALLOW_REMOTE` | 空（= 0） | 置 `1` 才允许连非本机 MySQL：**等于同意聊天记录离开本机**；桌面端「允许连接远程」勾选写的就是它，切回 SQLite 时自动清空 |
| `DB_SSL_CA` | 空 | MySQL 服务端 CA 证书路径：填了则连接走 TLS 并校验证书（远程库跨公网时强烈建议填）；表单里的「CA 证书」写的就是它 |
| `DB_SSL_NO_VERIFY_IDENTITY` | 空（= 0） | 置 `1` 只放宽「证书与主机名是否匹配」的校验（证书链仍然校验），仅给本机自签证书用（官方镜像证书 CN 是 `MySQL_Server_8.0.x`，用 `127.0.0.1` 连必然不匹配）；开启时后端日志会留一条 WARN，公网库不要开 |
| `JWT_SECRET` | 空（必填，≥32 位） | 登录令牌签名密钥，`start.ps1` 自动生成 |
| `JWT_EXPIRE_SECONDS` | `604800`（模板值） | 令牌有效期。**代码里没有内置默认值**，删掉这一行后端会报「缺少配置项」 |
| `MOCK_CODE` | 空 | 演示固定验证码，填了就用它；留空（默认）则每次随机 6 位。不要填 `000000` / `123456` 这类公开值 |
| `DEMO_CODE_MODE` | `0` | `0` = 不回显（验证码只写服务端日志）；`1` = 回显，**仅本机演示用——那种状态下任何能访问本机端口的人都能登录任意账号** |
| `AUTH_BUDGET_PER_MINUTE` | 空（默认 30） | 与账号无关的全局慢哈希预算：一分钟内最多做多少次 PBKDF2（注册 / 登录 / 假校验共用），超出返回 429。正常使用触发不到，只在压测与自动化场景需要调大 |
| `CODE_EXPIRE_SECONDS` | `300`（模板值） | 验证码有效期；同 `JWT_EXPIRE_SECONDS`，代码里没有内置默认值 |
| `DEEPSEEK_API_KEY` | 空 | 默认模型，不填也能启动 |
| `DASHSCOPE_API_KEY` | 空 | 选填，填了多一个 `qwen-flash` |
| `DEEPSEEK_BASE_URL` / `QWEN_BASE_URL` | 空 | 选填，接自建代理时改这两个 |

`UPLOAD_DIR` **不是给用户配的**：它只出现在测试与工具子进程里（覆盖附件根目录，避免测试写到真实 `data/uploads`），手工设置会让附件与备份对不上。

桌面端的后端地址与主题存在 `%APPDATA%\suixinwenda-desktop\config.json`，也可在应用「设置」里改。

`.env.example` 里 **`DB_*` 连接项（`HOST` / `PORT` / `USER` / `PASSWORD` / `NAME` / `ALLOW_REMOTE` / `SSL_CA`）全是注释掉的模板行**，
真正生效的只有 `DB_BACKEND` 与 `DATA_DIR`。在切换存储窗口里填表时，桌面端追加或改写的也是「生效行」，注释模板行不会被改动，
所以文件里会同时出现「注释模板 + 生效值」两套 `DB_HOST` 之类——功能正常，别当成重复配置去手改。

## 2. 存储判定口径

唯一口径在 `backend/core/db_info.py`：

1. `DB_BACKEND` 显式写了 `sqlite` / `mysql` → 用它；
2. 没写但 `DB_HOST` 有值 → MySQL（只看 `DB_HOST`：本机 MySQL 常见 root 空密码，用四项判据会把老用户误判成 SQLite）；
3. 其余 → SQLite。

附件按**库身份**分目录：`data/uploads/sqlite/`、`data/uploads/mysql-<host>-<port>-<库名>/`。
只用 sqlite / mysql 两层不够——本地 MySQL 与远程 MySQL 是两个库，共用 `uploads/mysql/` 时，
空库启动的孤儿清理会把另一个库的附件全判成孤儿删掉。备份文件名同样带这个库身份，
所以「升级前 / 恢复前 / 定期」三种自动备份在本地库与远程库之间各留各的最近 5 份。

### 切换存储

两种存储**互相独立**：切换不搬运历史、不删除任何数据，切回去就能看到原来那份。

| 当前 | 切过去看到 |
|---|---|
| MySQL → 本机 SQLite | 一个空库（MySQL 里的会话一条不少，仍在原库） |
| SQLite → MySQL | 原来那份 MySQL 数据（SQLite 里的会话留在原文件） |

技术侧要点：

- **密码必须非空**：`core/database.py` 对 `DB_PASSWORD` 是必填校验，空密码会让后端启动直接报「缺少配置项」，
  表现为「测试通过、切换必失败」。本机 MySQL 是空密码的话请先给它设一个。
- 端口必须是 1–65535 的整数；主机不能含空白字符。
- **表单回显当前生效值**：打开切换存储窗口时，主机 / 端口 / 用户名 / 库名取后端 `/health` 报上来的真实配置（密码留空待填）。
- 测试通过后界面会告诉你目标库是不是空的；**库非空时会提示「已有 N 个会话，切换后列表会显示这些数据」**。
- **密码加密存储**：桌面端用系统加密（Windows 走 DPAPI）写成 `DB_PASSWORD_ENC`，开发态写 `backend/.env`、打包态写 `userData/config.env`；
  只有手动跑 uvicorn 时才需要明文：在 `.env` 里临时写一份 `DB_PASSWORD` 即可（桌面端下次启动会把它重新加密）。
- 切换会**重启后端**（切换窗口里显示进度，期间主窗口的发送入口被禁用），失败自动回滚到原存储。
  切换前会先跑一次同样的连接探测：密码不对、库不存在、端口不通会当场给出中文原因。
- **切过去看到空列表是正常行为**，不是数据丢了；切回来即可。

### 远程 MySQL（可选）

主机填 `127.0.0.1` / `localhost` / `::1` 以外**任何**地址都算远程，必须同时勾选
「允许连接远程数据库（聊天记录会离开本机）」才会放行——没勾时表单当场拦住，后端也不会启动。

- **附件仍在发起请求的那台机器上**：数据库共享了，`uploads/` 没有。换一台电脑连同一个远程库，
  会话都在、图片会裂。要搬历史请用「导出数据 → 从备份恢复」。
- **传输加密**：在连接表单填「CA 证书」（云厂商控制台下载的 `.pem`），之后后端与「测试连接」都走 TLS 并校验证书。
  不提供「跳过校验」的开关——那等于把中间人攻击的门开着。
- **网络**：只映射 3306 到公网会被扫描爆破，建议内网 / VPN，或云上私网 + 安全组只放行你的出口 IP；
  账号用专用账号（`'user'@'你的IP'`）并只授权 `suixinwenda` 库，但**要保留建表权限**（首次启动会建表补索引）。
- 目标库请先 `CREATE DATABASE suixinwenda DEFAULT CHARSET utf8mb4`；切过去是空库，切换不搬数据。

## 3. 模型配置

模型不写死在 `.env`：在「设置 → 模型」里自己添加，兼容任何 OpenAI 协议接口。

- **添加时填四项**：显示名称、Base URL、API Key、模型 ID（例如 `deepseek-chat`）；
  另有两个开关：支持图片输入（关掉后前端禁用图片附件）、推理模型（只写进能力位，**后端当前不回传推理内容**）。
- **预置两个模板**（DeepSeek / 通义千问）只带地址与模型 ID，**Key 必须自己填**；也可以选「自定义」接中转站或私有化部署。
- **每个模型自带 Key**：选哪个模型就用哪个模型自己的凭据。
- **保存后自动重启后端**并立刻做一次轻量验证：有效显示「可用」，Key 错 / 模型 ID 错显示具体中文原因；失败时旧配置仍然有效。
- **Key 加密存储**：写在 `%APPDATA%\suixinwenda-desktop\models.json` 的 `apiKeyEnc`（safeStorage / DPAPI），
  界面只显示「已配置」，不回显；后端需要明文，由桌面端在启动时写一份运行时文件（退出即删）。
- **老用户自动迁移**：升级后首次启动会把 `.env` 里的 `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY` 加密搬进模型配置，之后以 `models.json` 为准。
- **手动启动后端**（不走桌面端）没有运行时文件，仍按 `.env` 的两模型逻辑工作。
- 没有可用模型时主区会显示「去添加模型」横幅；模型可以全部删掉，此时发送键禁用，重新添加即可恢复。

结构升级（新增列 / 索引）在启动时自动完成，改结构前会自动备份到 `data/backups/`（每个后端、每种前缀各保留最近 5 份）。

## 4. 备份 / 导出 / 恢复 / 一键清除

| 动作 | 产物 | 内容 | 用途 |
|---|---|---|---|
| **备份** | 一个 `.zip` | 数据库快照 + `uploads/` 里当前后端的全部附件 | 回滚：整库搬回来 |
| **定期自动备份** | 同上，文件在 `data/backups/before-auto-<backend>-<时间戳>.zip` | 同上 | 不点备份也有退路（默认开、7 天一次） |
| **导出** | 一个目录（`manifest.json` + 每表一个 `.jsonl`） | 业务表的结构化数据，**不含附件** | 换库、长期归档、逐行查看 |
| **恢复** | — | 从上面两种产物写回当前库 | 灾难恢复 |
| **一键清除** | — | 删会话相关表 + 当前后端的附件文件 | 清空重来 |

- 备份**只含业务表**（`users` / `conversations` / `chat_messages` / `chat_attachments` / `chat_summaries`）：
  老库里残留的 LangGraph `checkpoint*` 表已停用、体积占比极大且内容不可信，备份时会被跳过。
  `manifest.json` 的 `included_tables` / `skipped_tables` 写明了这次导了哪些、跳了哪些
  （白名单里有、但库里没建的表也会出现在 `skipped_tables` 里，用来暴露「这次没覆盖某张表」）。
- MySQL 备份优先用 `mysqldump`，机器上没有时自动改用内置导出（`SHOW CREATE TABLE` + 分批 `INSERT`，标准 SQL，可直接执行恢复），**不需要额外安装任何东西**。
  内置导出的产物是纯 SQL，恢复时整包交给 MySQL 执行，**不要自己按分号切**（字符串里含分号会切坏）。
- **恢复**支持三种来源，靠包内结构自动判别：备份 `.zip` 含 `db/suixinwenda.db` 走 SQLite 快照；含 `db/suixinwenda.sql` 走 MySQL 脚本（只能在 MySQL 后端上恢复）；「导出数据」目录（`manifest.json` + `*.jsonl`）走 JSONL。
- 恢复窗口里直接列出最近若干份备份 / 导出（按时间倒序、缺文件的不列）：点一行即选为来源，zip 行右侧的「设为附件」用于给导出目录补附件。
- 恢复的 `--force` 语义是「**先自动备份当前库，再清空当前库**」；不带 `--force` 时，目标库已有会话数据会被直接拒绝（不备份、不写库）。
  「一键清除」保留账号（`users` 不删），所以恢复时账号按 `username` 合并：已存在的复用其 id、**不覆盖密码与创建时间**。
- **导出不含附件**：要从导出目录恢复出附件，得另外指定一个备份包作为附件来源（UI 的「附件来源」/ CLI 的 `--uploads-from`）。
- **一键清除不可逆**，且会**物理删除**当前后端的附件文件；账号保留。

命令行等价物（都在 `backend/` 下执行，输出一行 JSON）：

```powershell
uv run python -m tools.backup  --out D:\bak\suixinwenda.zip      # 备份
uv run python -m tools.export  --out D:\bak\export-01           # 导出
uv run python -m tools.restore --from D:\bak\suixinwenda.zip      # 恢复（非空库需加 --force）
uv run python -m tools.restore --from D:\bak\export-01 --uploads-from D:\bak\suixinwenda.zip
uv run python -m tools.purge                                    # 干跑：只统计
uv run python -m tools.purge   --yes                            # 真清
uv run python -m tools.db_info                                  # 当前后端与连通性
```

定期自动备份：每次启动后端就绪后检查一次「最近一份备份（手动或自动）的时间」，超过设定天数就静默生成
`before-auto-*` 包，与升级前 / 恢复前的备份**各留各的最近 5 份**；执行期间与手动备份一样挡住退出。

## 5. 接口清单

统一前缀 `/api/v1`，跑起来后 `/docs` 有可交互文档。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/health` | 健康检查。响应里的 `data.managed` 表示是否由桌面端托管（`start.ps1` 靠它区分「已在运行」与「用户自己起的实例」），`data.pid` 是后端进程号 |
| POST | `/send_code` | 发送验证码（演示直接返回；注册已不需要，仅兼容保留） |
| POST | `/register` | 注册（账号 + 密码即可，可选昵称；直接返回令牌） |
| POST | `/login` | 密码登录 |
| POST | `/login_by_code` | 验证码登录（无则自动注册；前端已收起入口） |
| PATCH | `/me` | 改昵称（需登录） |
| GET | `/get_models` | 可用模型列表（含 `vision` / `reasoning` / `speed` 能力声明） |
| POST | `/models/verify` | 用指定模型真发一次极轻量请求，验证 Key / 模型 ID |
| POST | `/chat` | 流式对话（SSE）；`regenerate: true` 时覆盖最后一条回答 |
| POST | `/chat_upload` | 带附件的对话（SSE）；`files` 可多个，兼容单 `file` |
| GET | `/conversations` | 会话列表（`?limit=` 默认 100、上限 500；`?offset=` 翻页） |
| GET | `/conversations/{id}/messages` | 会话消息（`?limit=` 默认 50、上限 200；`?before_id=` keyset 往前翻） |
| GET | `/conversations/{id}/memory` | 该会话的对话历史（模型这一轮看到的上下文，含图片元数据） |
| PATCH | `/conversations/{id}` | 重命名会话 |
| POST | `/conversations/{id}/revert` | 回退一步：恢复上一版回答 |
| DELETE | `/conversations/{id}` | 删除会话（连带清记忆与附件） |
| POST | `/conversations/claim` | 登录后认领匿名会话 |
| GET | `/attachments/{id}` | 附件原文件（图片灯箱 / 另存 / 系统打开） |
| GET | `/attachments/{id}/text` | 附件抽取正文（文档预览） |

流式返回格式：

```
data: {"content": "逐字文本"}
data: {"conversation_id": 12}
data: {"error": "中文错误提示"}
data: [DONE]
```
